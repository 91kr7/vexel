# timing-scale — Index

| Component | Type | Path | Responsibility | Spec |
|-----------|------|------|-----------------|------|
| Server timing scale | backend module | `server/src/timing/timing-scale.ts` | The one place a server cadence is declared from: `VEXEL_TIMING_SCALE` read once at import — `1` when unset, refused at import with the variable and the value named when it is not a plain decimal from 0.1 to 10, never taken silently as `1` — and the `cadence(ms)` helper every scaled cadence goes through, rounding to a whole millisecond and never below one | `specs/server-timing-scale.md` |
| Timing-scale endpoint | REST endpoint | `server/src/timing/timing-routes.ts` | `GET /api/timing-scale`, answering the factor this process is using so the browser — which has no environment to read — can run on the same clock; nothing is asked of the daemon, so it answers whatever state the daemon is in | `specs/timing-scale-endpoint.md` |
| Client timing scale | client module | `client/src/timing/timing-scale.ts` | The one place a client cadence is declared from: the factor the running page uses — `1` until the entry point sets it, so a page that never learns one runs at the shipped rhythm — and the `cadence(ms)` helper every scaled cadence goes through, with the same rounding and the same floor | `specs/client-timing-scale.md` |
| Timing-scale reader | client data client | `client/src/timing/timing-scale-client.ts` | Reads the factor from the server's endpoint at bootstrap under a bounded, unscaled 2 s wait; a refusal, a failure, an unusable body or a wait that runs out all give `1`, so a server that never answers leaves the product on its own rhythm rather than a blank page | `specs/timing-scale-reader.md` |
| Suite timing configuration | configuration | `client/playwright.config.ts` (`webServer.env`), `server/package.json` (`test:api`) | The factor each automated pass runs the product at — `0.2` for the Playwright suite's web server and for the daemon-backed server pass, deliberately unset for `test:unit` so the tests pinning a shipped cadence value keep measuring it | `specs/suite-timing-configuration.md` |
