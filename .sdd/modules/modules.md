# Modules

| Module | Responsibility | Index |
|--------|----------------|-------|
| ui-library | The internal, domain-agnostic UI library (`client/src/ui/`): design tokens, the glass material, layout, navigation, control, cross-reference, metric and feedback primitives — the only place allowed raw DOM tags and CSS. | `ui-library/index.md` |
| app-shell | The application shell that composes the UI library: navigation data, the "Vexel — Docker Control" shell, the identity and legal notice the About screen carries with the build-time version constant behind it, the header's refresh control with the reload signal and the refresh client behind it, the keeper the container detail's inspect data and its process listing store their readings through, and the application-wide confirmation/error/progress/connection/event/cross-navigation services. | `app-shell/index.md` |
| dashboard | The Dashboard screen and the host overview behind it: the summary tiles, the live container activity, the disk-usage breakdown, the recent daemon events, and the navigation from each of them to the screen owning the object. | `dashboard/index.md` |
| docker-access | Server-side Docker access layer: the Engine API client (unix/TCP+TLS/ssh, version negotiation, typed errors), the local `docker`/`compose`/`buildx` CLI runner, and the log written before every call on either channel — shared by every future domain area that talks to Docker. | `docker-access/index.md` |
| refresh-cache | The values the interface asks for repeatedly, held server-side and kept current: a kind registered with its read and period, served without calling the daemon, refreshed by one background worker each, marked due by daemon events and by the application's own operations, refreshed only while asked for, discarded when the active context changes, read again in full on the operator's request through its own endpoint, kept read by a hold that suspends its expiry, and announcing every value it stores to whoever subscribes. | `refresh-cache/index.md` |
| list-order | The one rule every server-side list of named objects is ordered by — a fixed-locale, case- and diacritic-insensitive, numeric-aware name comparison made total by an exact identity comparison — and the build-time guard that no ordering is written outside it. | `list-order/index.md` |
| check-budgets | The rules every check of this repository follows, and the build-time guard behind each: the patience it declares — a test's budget covers what its steps spend, so every step budget is smaller than the budget of the test that runs it, measured against the default declared in the Playwright configuration — and the daemon it starts from, every daemon-backed test file emptying Docker before it runs, per-file in the end-to-end tree and by preload in the server's. | `check-budgets/index.md` |
| connectivity | Daemon reachability, negotiated API version and CLI/plugin availability: the server status service and its endpoint. | `connectivity/index.md` |
| events | The live daemon event stream, server-side: the subscription to the daemon's `/events`, the normalization and republication of what it carries, the backlog and the notification of its own connection dropping or returning. It is carried to the browser by the live channel. | `events/index.md` |
| live-channel | The one connection a window opens: the SSE endpoint carrying the daemon events and every value the server's refresh cache holds, the publisher that writes each stored value to every open channel and holds the cache's demand while one is open, and — in the browser — the single client that routes each message and the store the screens read what it delivered from. | `live-channel/index.md` |
| local-persistence | Local, per-user persistence (preferences, console history, analysis-cache index) and host-path validation: the local store, the content-addressed analysis cache, the host-path validator, their endpoints, and the client's preferences client/hook. | `local-persistence/index.md` |
| containers | Container list, creation, lifecycle, inspection/configuration, logs, live statistics and processes: the Engine API listing/lifecycle/prune/inspect/config service and the CPU/memory sampler gated on a count of live subscriptions, the creation service with image resolution and pull, the log- and stats-streaming services, the process listing, their endpoints, the client's containers data clients/hooks, the Containers screen with its create/run form, and its detail panel with the logs, stats and processes views. | `containers/index.md` |
| images | Image list and registry-facing actions: the Engine API listing/inspect service, the pull/push/tag/untag/remove/prune transfer service, their endpoints, the client's images data clients/hooks, the Images screen, its inspect detail panel, the layer explorer and the layer-efficiency/secret-signal view. | `images/index.md` |
| image-analysis | Per-image layer stack, per-layer changesets, layer-efficiency/duplicate/secret-signal findings, and runtime-independent filesystem browsing with in-tree file operations: manifest/config-derived layer metadata, cross-image shared-layer detection, cached and cancellable per-layer changeset computation with OCI whiteout awareness and content hashing, waste/duplicate-content/secret-pattern analysis derived from it, cached and cancellable filesystem extraction (an unstarted intermediate container, cleaned up whatever happens) with lazy tree reads, entry metadata/content/search/export over the extracted tree with containment against traversal and escaping symlinks, the association between a layer's build step and the build-cache record that produced it (with an explicit, reasoned unavailability), and their endpoints. | `image-analysis/index.md` |
| volumes | Volume list, inspect, create, remove and prune: the Engine API listing/inspect/create/remove/prune service merging in size and mounting-container data, its endpoints, and the client's volumes data client/hooks. | `volumes/index.md` |
| networks | Network list, inspect, create, remove, prune and container attach/detach: the Engine API listing/inspect/create/remove/prune/connect/disconnect service merging in attached-container data, its endpoints, and the client's networks data client/hooks. | `networks/index.md` |
| volumes-networks | The Volumes & networks screen: the two-panel layout with the Volumes panel (list, inline inspect, create, remove/prune) and the Networks panel (list, inline inspect, create, remove/prune, container attach/detach). | `volumes-networks/index.md` |
| registries | Configured registries and what can be pulled from them: the inventory from the local Docker configuration and the daemon's registry settings (account, credential store, authentication state, plain-http flag), held by the server, login/logout delegated to the host credential store so no secret is ever held by the application, anonymous repository/tag browsing with per-tag sizes, their endpoints, the client's registries data client/hooks, and the Registries screen. | `registries/index.md` |
| compose | Compose project discovery, stack lifecycle and per-service scaling, compose file read/validated write/validation (the sole consumer of host-path validation, REQ-116), and aggregated per-service log streaming — all through the `docker compose` CLI channel — their endpoints, the client's compose data client/hooks, and the Compose screen. | `compose/index.md` |
| builders | buildx builder inventory and management (create, remove, select-active), the build-cache inventory and prune, and the reverse lookup from a cache record to the images and layers it relates to — through the `docker buildx` CLI channel — their endpoints, the client's builders data client/hooks, and the Builders & cache screen. | `builders/index.md` |
| contexts | Docker contexts and the daemon behind them: the inventory covering every endpoint kind with create (local socket / SSH), select-active and remove through the CLI channel and the local Docker configuration, the daemon-information reading of the active context, their endpoints, the client's contexts data client/hooks with the active-context broadcast every cached view listens to, and the Contexts screen. | `contexts/index.md` |
| plugins | The plugins of the active installation: the CLI plugin inventory of the local Docker installation and the daemon's managed-plugin inventory, each degrading to a stated reason when it is not exposed, read together as one round the server holds whole, the privileges a reference asks for and the install that runs only once exactly those are granted, enable/disable/inspect/remove — none of them forced —, their endpoints, the client's plugins data client/hook, and the Plugins screen. | `plugins/index.md` |
| system | Reclaimable disk space and the prunes over it, and the Docker baseline the product's coverage claim refers to: the breakdown by stopped containers, dangling images, unused volumes, unused networks and build cache, the per-category and scoped system prune delegating to each area's own prune, the declared Engine API/CLI baseline reported next to the connected daemon's own versions, their endpoints, the client's system data client/hook, and the System & prune screen with its shared-daemon warning. | `system/index.md` |
| raw-console | The escape hatch that carries the full-coverage claim: what a typed command line means before it runs (argv tokenization, Engine API entry grammar, destructive and credential recognition), the CLI channel running an arbitrary `docker` command against the active context with streamed output and cancellation, the API channel returning the daemon's raw status and body, the history kept in the local store and never holding a possible credential, their endpoints, the client's console data client/hook, and the Raw console screen. | `raw-console/index.md` |
| coverage | The product's own coverage statement: the capability-area map with its console-only and not-applicable gaps and their reasons, the baseline query joined with it, the coverage matrix the About screen carries, and the build-time guard that the application reads nothing of the daemon's swarm — the area being declared console-only. | `coverage/index.md` |
| timing-scale | One factor, `VEXEL_TIMING_SCALE`, multiplying every cadence of the product and no tolerance: the server's declaration read once at import and refused there when it is malformed or out of range, the endpoint that carries the figure to a browser with no environment to read, the client's declaration and the bounded, unscaled read that fills it at bootstrap, and the factor each automated pass runs the product at. | `timing-scale/index.md` |
| server-app | The server entrypoint that composes every server module into one running Express app, the serving of the built interface from that same process, origin and port, and the repository-root commands that build and run it. | `server-app/index.md` |
| measurement | The measurements taken over this repository rather than over the product: the coverage command that runs the four suites and merges what each of them executed into one figure per workspace and per source file, the wiring that makes a suite record it, the mutation command that changes both unit trees on purpose and reports the changes no test caught, and the report store every measurement writes its report file through. | `measurement/index.md` |
