## What the implementer must not get wrong

- **Never make the string `Copy` the criterion.** Every instance in this build says `Copy`, which is a
  fact about this build and not about the design: the component's own `label` prop made an icon-only
  or differently-worded instance one edit away. A check that greps for the word passes on a build
  that still ships one, and that is this report's single most likely failure (REQ-25).
- **Deleted, not orphaned.** `CopyButton.tsx` is removed from disk and from the library's entry
  point, and `copyValue` is removed from the item type so the compiler refuses a caller that passes
  one. A component kept "in case", a prop kept with no renderer, or a spec kept for a deleted file
  each mean the product still holds the thing he asked to remove.
- **Thirteen props, not twelve. Twenty-four sites, not twenty-two. Eight screens, not nine.** The
  analysis's lists were right and three of its totals were not; the totals have since been corrected
  in the analysis itself. Work from the enumeration in `../requirements.md`, and recount rather than
  copy.
- **Three sites render one control per row** — console entries, health-log blocks, definition bands.
  Checking the first row is checking nothing; the daemon decides how many there are.
- **Nothing replaces it, under any name.** Copy-on-click, a context-menu entry, a keyboard shortcut,
  click-to-select-all, a `title` carrying the full id, an icon-only variant, hiding it at a
  breakpoint. Each is the same affordance renamed, and the instruction admits none of them.
- **Do not "finish" a band by clamping its value.** The values are longer than they look and the
  operator now selects them by hand; an ellipsis, a `text-overflow` or a `user-select: none` added
  in the tidy-up turns a convenience loss into a data loss (REQ-17).
- **Do not re-tune bug-4's column rule.** The `Id` band getting shorter is the *point*; the minimum
  band width comes from `Created`, so no column count changes. If one does, the change went into the
  wrong component (REQ-15).
- **Do not delete a test file to remove an assertion inside it.** Coverage is removed only where the
  behaviour it covered is removed; `property-columns-contract.test.tsx` in particular is bug-4's
  contract coverage and most of it has nothing to do with the clipboard (REQ-30).
- **Do not touch `check-ui-conformance.mjs`.** The removed control carried no selector, token, blur
  or z-index. An edit to that file is a signal that something went where it should not have; report
  it rather than make it (REQ-32).
- **Report the three costs in the batch report**, in the human's own words from `../requirements.md`
  F5: a full id is now a hand-selection in a JSON block, a whole log can no longer be put on the
  clipboard at all, and a join token can no longer be taken without being displayed. They are not
  defects and they are not to be mitigated — they are the part of this fix he has to read.

## Verification

**Test runs in this batch are batch-scoped, in both phases:**

- `npm run lint`
- `npm run test:typecheck -w client` — which is where REQ-8 is actually proved: with `copyValue` gone
  from the item type, a call site that still passes one **fails to compile**, across `src`, `test`
  and `e2e`
- `npm run test -w client` — including the UI-conformance check, **unmodified** and passing
- this batch's own e2e specs, **each run on its own**: INT-2's eight-screen sweep, INT-3's geometry
  spec, and — as this batch's evidence that the four delivered siblings are undisturbed — bug-4's
  `image-detail-property-columns.spec.ts` and `property-columns-rule.spec.ts`, plus the delivered
  `containers.spec.ts`, `container-logs.spec.ts` and `raw-console.spec.ts` after INT-10

**Neither phase launches the complete unit suite or the complete e2e suite.** The human has
instructed that both run **once, at the end of the whole five-report tranche**, on his own daemon; a
subagent starting a full run competes with him on that same daemon and fails in plausible-looking
places. If a change appears to need wider coverage than the list above, that is a question for the
orchestrator, not a reason to widen the run.

**The evidence this batch is judged on** (REQ-28): INT-1, INT-2 and INT-3 are run **before INT-4 to
INT-7 exist** and reported with the figures they produced on the delivered build — one clipboard
implementation, one export, five render sites, thirteen `copyValue` props, twenty-four instance
sites, every instance labelled `Copy`, and an `Id` band of 43px against its neighbours' 33px —
beside the same figures after. A "before: failed" with no figures is not evidence on a removal, and
a green run whose check could not have distinguished an icon-only instance is not evidence at all.
